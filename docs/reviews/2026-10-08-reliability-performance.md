# ZB202 连接稳定性与前端性能检查

检查日期：2026-10-08（香港时间）。范围：InfluxDB/MQTT 桥接、总览页面、三维页面、历史查询、资源加载、构建及控制通道。检查依据为源码、真实只读请求、桥接日志、页面运行状态和隔离模拟测试。未操作真实插座。未执行服务器端配置变更。

## 结论

频繁显示 InfluxDB connection lost 不属于期望运行状态。现场捕获到了真实查询失败：`socket hang up` / `ECONNRESET`。后续查询和页面可恢复，说明并非数据库持续不可用。仅凭客户端证据无法区分数据库、反向代理、网络中间设备或本机网络的责任。此前默认 10 秒查询超时、固定重连和查询失败时立即标记断开也会放大用户感知。

## 已实施

- InfluxDB 查询默认超时改为可配置的 30 秒；失败报告包含错误类型、错误码、最后成功时间和连续失败次数。页面告警显示查询错误与桥接断线的不同原因，错误文本经过 HTML 转义。
- 只读轮询遇到 ECONNRESET/EPIPE 后重试一次；持续失败按完成时间退避调度，最多 60 秒。不重试实体控制命令。
- 去掉实时和天气查询在 tail 前的额外 sort；Flux 原生数据按时间返回。查询优化原则参考 [InfluxDB 官方文档](https://docs.influxdata.com/influxdb/v2/query-data/optimize-queries/)。
- 每个字段的历史查询按范围使用 last 聚合，目标约 600 个时间窗口，避免 30 天历史全量进入浏览器。该历史用于趋势展示，不能代替原始事件导出。
- WebSocket 增加协议心跳、16 KiB 消息限制、慢客户端缓冲保护和浏览器来源主机校验。前端重连指数退避并增加抖动，退出页面时清理连接、观察器和渲染资源。
- 历史请求限制同时处理数量；忙碌请求返回明确错误；前端历史加载有超时并在断线时清理。
- MQTT 队列最多等待 16 项，同一设备等待队列避免重复；发布增加 10 秒超时。MQTT 发布成功仍须等待设备遥测确认，发布成功不代表实体执行成功。
- 三维页面每 100 ms 合并遥测引发的 UI 更新；没有设备/选择/主题/模型状态变化时不重复重设 BIM 高亮。
- 后台页面跳过 WebGL、标签和定时 UI 刷新；前台标签及碰撞整理最多每秒 30 次，WebGL 保持原有帧循环。
- 最新值按字段时间戳更新，避免重放旧数据覆盖新值；历史内存每字段最多 2000 点；去重包含字段值，避免同一时间戳新增字段被丢弃。
- 模型下载增加 60 秒超时；模型属性、设备名称和告警中的动态文本补充 HTML 转义。

## 仍需处理或核实

| 优先级 | 问题 | 后续措施 |
| --- | --- | --- |
| 高 | 实际上游仍有 ECONNRESET，短暂重试有时也失败 | 对齐桥接错误时间与 InfluxDB/代理日志；检查校园网络/VPN、代理连接关闭、服务端负载与超时。不能仅通过延长前端超时保证消除断线。 |
| 高（联网部署前） | 现有 InfluxDB URL 为 HTTP，MQTT 为 mqtt://，WebSocket 本地服务无用户身份认证 | 管理员提供 HTTPS/TLS 服务及证书，再配置；对外部署时使用身份认证及控制权限。来源校验不是身份认证，不应直接暴露控制端口。 |
| 高（HTTPS 部署前） | 页面按 HTTPS 构造 wss://host:8787，而桥接当前仅提供明文 ws:// | 在反向代理配置 TLS WebSocket 转发，或提供受保护的同源代理端点。当前本地 HTTP 页面可用，不能据此确认 HTTPS 部署可用。 |
| 中 | HKO 太阳辐射拉取出现 fetch failed，重启后可能暂时没有辐射数据 | 核查本机到 HKO 的外网、DNS/代理和数据源可达性。当前不把写入失败的数据当成已持久化数据展示。 |
| 中 | Three.js/Fragments 资源仍较大 | 构建中三维入口约 704 kB、Fragments 动态块约 4.15 MB、worker 约 3.27 MB，均为未压缩体积；部署启用压缩和版本化缓存，进一步性能剖析后再调整加载顺序。打包警告仍存在。 |
| 中 | 外部 Google Fonts 请求依赖外网，图标包包含多个字体格式 | 考虑自托管所需字体、减少字重、仅保留浏览器需要的图标资源。产物存在不表示所有格式均会被下载。 |
| 中 | 页面 Online/Offline 来自数据库可读性和是否存在记录；不代表设备心跳 | 页面应区分数据可用、最后采样时间与设备联网状态；安静传感器不能据此判为离线，旧记录也不能证明现在在线。 |
| 中 | Occupancy 使用存在传感器数量显示 people | 存在信号不能直接保证人数准确；应改为占用点位或由实际计数数据支持人数。 |
| 中 | 开发页面热更新/卸载期间捕获到 Fragments model not found | 已增加关闭标志及阻止新的高亮更新；仍应在频繁模型切换和长期运行下继续检查 worker 生命周期。 |
| 未完成验证 | 依赖漏洞审计无法连接 npm registry，UI Skills CLI 也无法连接其远端服务 | 恢复网络后执行 npm audit。此次不能声称依赖不存在漏洞。采用已安装的性能技能规则进行代码检查。 |

## 验证

- `npm run test:resilience`：通过。隔离模拟数据库验证成功遥测、503 错误诊断、失败后恢复、非法历史请求、null 消息、外站来源拒绝与历史降采样。
- `npm run build`：通过；仍有上述体积警告。
- `npm run test:bridge`：曾通过，返回 24 台传感器的 87 个字段；期间一次在上游断线期间超时，最终复测再次通过。因此真实连接稳定性尚未证明，不能用模拟测试通过替代真实稳定性结论。
- 页面实测：模型、天气和室内数据、需求曲线可加载；观察到了恢复后的 26 个数据可用点位及无活动告警状态，也观察到了数据库断线告警。
- `git diff --check`：通过。

未做长期压测或前后 FPS/CPU 对比，本次不提供未经测量的性能提升百分比。
